Six ways through the toolset

Every path a person can take from a PowerPoint deck to a filled-in slide, the gates that stop each one, and how far each step has actually been proven. The gates are the design; the buttons are just the order they come in.

What each side owns

Two files and a toolbar. The deck knows which slide is which and what period it reports; the workbook knows what the words are and how each field should be written. Neither is a copy of the other, and every button below moves something across that line.

1 · A slide type you have never used

once per type, ever

Teaching the tool what a slide of this kind looks like. Nothing here repeats each quarter — get it wrong and you redo this, not the quarter.

The estimate here has been wrong before. An eyeball count put one real slide at ~25 trackable fields; the audit found 52. That 3× gap is the whole argument for Setup C existing.

2 · A new quarter

the main event · 4× a year

The numbered path. Everything before 3. Publish is reversible; everything after it is verified against the file on disk rather than what PowerPoint believes.

Why step 0 re-opens the file. It used to write the period, read it straight back through PowerPoint, and report success — which reads a cache and confirms its own write. On 8 Aug it said “Deck period is now Q4F26” against a file untouched for three days.

3 · A project joins mid-quarter

the growth case

You add a row to the register for a project that has no slide yet. There is no separate button for this — sync notices, and asks.

This is a real deck, not a hypothetical. On 31 July the live deck had 43 orphaned rows against 46 slides. A hand-assembled board pack is missing most entities by design — so unbounded creation would have fired at exactly the moment the content was finished and about to be shown.

4 · Reading every change before it lands

when sync is too blunt

The same write path, a different reading surface. Prose can never be batch-approved, so 43 rewritten paragraphs come here rather than into a dialog.

5 · Parity — the question the whole thing answers

stated on every sync

After a sync, the deck and the register either agree or they do not, and the report says which. Both directions are counted, because until today only one of them was.

6 · When something is wrong, and what is still missing

rare, and rarely at a good moment

7 · Orphaned code — built, still shipping, acts on nothing

audited 9 Aug 2026

Found by a static scan that reads the toolbar's real wiring and asks the reverse of the usual question: not does this button work, but can a person reach this at all. Two capabilities had been built, tested, and left unreachable before it existed.

HealthWhatState
cadence — 6th parameter of WriteDraftingSheet Production passes five arguments, so it is permanently Nothing. Built for Quarter = ALL, retired 3 Aug. Every rollover therefore clears every drafting row.
FieldVolatility — static / variable You are asked this once per field during the most expensive interaction in the tool — roughly 52 times on a real deck — and nothing ever reads the answer.
FieldType — text / number / currency / date Collected, normalised, written to the grid, never acted on. Deliberately inert with a written reason, but it still costs a prompt per field.
"Quarter" as the register's column header A hardcoded literal in two places. Renaming it to Period — which is what everything else now calls it — needs a migration and a back-compat read.
Removed today Timeline.bas (zero callers anywhere), OnboardFlow.bas, Register.bas, RegisterSeed.bas, and four buttonless entry points — about 1,100 lines that shipped in every build. With them went Status, Seed/Draft/Approved, Quarter = ALL and Cadence as things a person could still meet.
A question a column cannot answer is not a setting, it is a toll. Two of the rows above are asked of a person during setup and read by nothing — together they account for two of the three prompts per field, on ~52 fields.

8 · Capability gaps — things a person still cannot do

the honest list
HealthGapWhat happens instead
Retire a slide or a project Nothing removes a slide the register no longer mentions. It shows as a parity mismatch and you fix it by hand — and until today it did not even show as that.
Three of five prose panels Strategic Alignment, Problem and Project Progress have no recipe and no tagged shape. They are hand-typed every quarter, and a stale one is invisible to every check the tool has.
A maintained list of linkage codes Strategic Alignment must cite codes it can check. With no list, the honest output is [TBC] — which is the recipe working, not failing.
Provenance that survives a rollover Source citations live only on the drafting sheet, which is cleared at every period change. So the record answering “why does it say 90%?” has a lifespan of one quarter.
Anything but text Pictures, shapes, tables and charts are named in the specs and out of scope in the code. Parked deliberately until one field has gone end to end with real content.
A real quarter, produced The one measure that matters, and still zero. Everything above is what stands between here and it.
Keeping this current. The source lives at docs/use-cases.html in the deck-sync repo, next to the code it describes. Any change to the toolbar, a gate, or a health state belongs in the same commit as the change itself — a status page that lags is worse than none, because it reads as verified.
